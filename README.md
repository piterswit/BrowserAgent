# BrowserAgent

BrowserAgent 由 Windows 本地控制软件和 Chrome 扩展 **FB Browser Bridge** 组成。软件通过本机 WebSocket 连接浏览器，可对选中的 Facebook 账号执行首页浏览、Reels 浏览、小组浏览、取消已发送的好友请求和随机更换头像。

![插件图标](WS%20Browser%20Bridge/icon/bridge-128.png)

## 功能

| 功能 | 本地软件 | 扩展弹窗 | 执行行为 |
| --- | --- | --- | --- |
| 账号连接与识别 | 显示账号头像、名称、FB ID 或用户名、状态和结果 | 连接 | 新建临时后台个人主页，读取后关闭 |
| 首页活跃 | 首页活跃 | 自动活跃 | 打开首页，分段滚动、停留，低频点赞、评论、分享快拍和加组 |
| Reels 活跃 | Reels活跃 | 活跃 Reels | 持续翻页，支持左右按钮、横向与纵向播放器，低频点赞 |
| 小组活跃 | 小组活跃 | 活跃小组 | 打开小组动态，浏览并低频互动 |
| 自定义活跃 | 自定义活跃 | 自定义活跃 | 在当前 Facebook 页面活跃 5 分钟，不跳转到首页或小组动态 |
| 停止活跃 | 停止活跃 | 无 | 取消所有活跃任务、等待和滚动，不跳转当前页面 |
| 取消好友请求 | 取消好友请求 | 取消好友请求 | 打开已发送请求列表，逐个取消；遇到限制提示或连续失败停止 |
| 批量换头像 | 选择目录、换头像 | 无 | 每个账号随机选图，在独立任务页上传并保存，关键步骤激活任务页 |
| 定位浏览器 | 账号右键菜单 | 无 | 被其他窗口遮挡时切到前台，最小化时先恢复；不导航原页面、不更新账号状态和结果 |

首页、小组和自定义活跃每次运行 5 分钟，到时停止，不刷新页面。Reels 不设结束时间，可持续翻页，直到手动停止、连接断开、关闭任务页或离开 Reels 页面。每个浏览器配置只运行一个活跃任务，重复注入不会叠加循环。页面隐藏、正在输入、存在非播放器弹窗或用户刚进行鼠标/键盘操作时暂停；用户操作后至少等待 10 秒。首页、小组和自定义任务导航离开原路径会结束；Reels 允许在不同视频地址之间切换，新页面加载后恢复同一任务，停止后不会恢复。

Reels 优先点击可见的“下一条/上一条”按钮，约 6% 的翻页尝试回看上一条，不连续回翻；没有按钮时查找视频所在的滚动容器，按实际布局向左/右或向上/下翻一屏，并支持 RTL 横向布局。首次等待 1–2 秒；之后通常观看 3–8 秒，结合视频剩余时长选择停留时间。没有时长信息时通常等待 3–6 秒；少量快速略过（1.5–3 秒）或较长停留（8–12 秒）。箭头点击前另有 0.2–0.5 秒等待。滚动容器翻页使用完整一屏，避免 CSS 吸附把小步滚动拉回原视频。停止支持在翻页和观看等待中取消，不会补发点击。

首页、小组和自定义任务首次滚动约在 1.2 秒后进行，之后根据当前可见帖子的文字量安排阅读停顿：通常 1.5–6 秒，少量略读停顿 0.8–1.6 秒，较长停留最长 9 秒。距离以视口高度为基准，在短滚动、半屏和接近整屏之间变化，偶尔小幅回看；滚动速度先加快再减慢，时长约 0.2–0.8 秒。不会用固定间隔、固定距离连续刷动。这些是交互测试启发式参数，不是真人行为或规避平台检测的保证。

首页、小组和自定义任务自动定位页面实际滚动区域，支持 `body` 不滚动、内容放在内部滚动容器的布局。隐藏、透明或视口外的菜单/弹窗不阻止运行；空的搜索框自动聚焦不会阻止浏览，但会阻止自动互动。可见的用户弹窗、输入草稿、后台标签页和近期用户操作仍会暂停。暂停原因或实际脚本异常会显示在执行结果列，启动前会检查控制器和循环是否就绪，不再仅凭文件注入成功显示活跃。

首页、小组和自定义活跃保留自动点赞、评论、分享快拍、加入小组，均会产生真实账号操作，请仅在有授权的测试账号和内容上使用。首次互动尝试在启动约 45–75 秒后；后续尝试间隔 90–150 秒，每次只选一种有有效目标的动作。每次 5 分钟任务最多尝试点赞 2 次、评论 1 次、分享 1 次、加组 1 次，受总间隔限制通常不会全部发生。没有目标或流程无法确定时也消耗本轮间隔，不会密集重试。Reels 仅低频点赞，保留单页面运行最多尝试点赞 2 次的限制，不限制翻页时长。

点赞跳过已赞按钮，并在点击前再次校验状态；评论、分享需要能读取稳定帖子标识，加组需要明确小组链接，定位不清楚时跳过。动作开始前记录尝试，避免提交结果不确定时重复操作。同一页面内按帖子/小组标识去重记录保留最多 24 小时，刷新页面会清空；不是跨浏览器或服务端去重保证。评论使用 `activity_interactions.js` 中的短句模板，不覆盖已有草稿；分享仅选择本次打开菜单中的快拍入口，加组遇到入组问答或审核弹窗不自动填写。

所有步骤中的等待都可被“停止活跃”取消。用户输入、切换后台或出现非本任务弹窗时中止当前互动；已填入但未发送的评论保留，不自动重试。停止不能撤销已经提交的点赞、评论、分享或入组请求。测试脚本也不盲目关闭用户弹窗，只会在评论输入已清空时尝试关闭本次打开的评论窗口。阅读停顿和有限时长用于交互测试、减少干扰，不能保证 Facebook 不会识别自动化，也不能保证账号安全；请遵守平台规则。

## 环境与安装

- 本地软件使用 Windows、Python 3.10 或以上版本；浏览器和软件运行在同一台电脑。
- 扩展要求 Chrome 118 或以上版本。其他 Chromium 浏览器需支持相同扩展 API。
- 多账号使用独立浏览器用户配置，每个配置加载扩展并登录对应账号。一个配置内的多个标签页共享登录状态，不能当作多个独立账号。

安装依赖并启动本地软件：

```powershell
python -m pip install -r requirements.txt
python server.py
```

浏览器打开 `chrome://extensions/`，开启“开发者模式”，点击“加载已解压的扩展程序”，选择仓库中的 **WS Browser Bridge** 目录。

## 连接账号

1. 先启动本地软件，再在对应浏览器配置中登录 Facebook。
2. 点击扩展图标，再点击“连接”。也可以访问 `https://www.facebook.com/?fb_bridge_connect_extension`。
3. 扩展在新建的后台标签页打开 Facebook 首页，读取账号名称和个人主页标识；信息不完整时再访问 `/me` 补充，完成后关闭该标签页。不会导航用户原来的页面，也不会强行切回之前的标签页。
4. 本地列表显示已连接账号。识别失败时会显示原因；完成登录或验证后，再点击扩展的“连接”重新识别。

FB 数字 ID 优先从个人主页 URL 和公开页面元数据读取；页面没有提供数字 ID 时显示个人主页用户名。用户名与插件连接 ID 都不是 FB 数字 ID。列表按连接 ID 管理，账号同名不会覆盖。

账号优先从首页已登录账号模块、结构化数据和个人链接读取，再补充个人主页元数据与主体标题，排除 Notifications、通知等界面标题。首页缺少信息时，在同一个临时页尝试个人主页；已识别的 ID、名字和头像分别保留，缺少一个字段不会清空其他字段。读取失败的具体原因显示在执行结果列和本地日志中。

头像只从当前账号模块、本人主页头像或账号入口读取，不使用首页动态作者头像或无法确定用途的 `og:image`（可能是封面）。读取后缩小成 36px PNG，通过本机连接传给软件；读取失败时显示默认头像，不随意填入其他图片。账号列表行高为 40px，超出缩略图尺寸的图片会缩小。确认更换头像成功后会尝试刷新列表头像。本地界面使用与插件相同的图标，启动时居中显示。右键账号选择“定位浏览器”，只定位该行所属的浏览器配置；不会对所有选中账号执行定位。

本地软件监听 `127.0.0.1:8765–8769`。扩展按顺序尝试端口，每 15 秒发送心跳。端口间隔约 0.75 秒，每次尝试最多等待 3 秒；全部失败后按 5、10、20、30 秒退避重试，最多一个连接和一个重试计时器。后台休眠时由一分钟的 alarm 兜底唤醒，实际重连可能延后。软件重启或连接断开后自动重连，不重复弹出连接失败提示；Chrome 自身仍可能记录 WebSocket 连接拒绝的网络日志，这不是未捕获的插件异常。

连接关闭后软件立即清理账号并停止页面活跃；关闭最后一个普通浏览器窗口时主动断开并取消重试，重新打开窗口后恢复连接。软件每 3 秒检查已关闭连接和心跳，心跳超过 60 秒时移除异常失联账号。

## 批量操作

在账号列表中用 Ctrl 或 Shift 选择多个账号，再点击操作按钮。每个独立浏览器配置分别执行收到的命令。

首页、小组、Reels 和自定义活跃优先使用当前 Facebook 标签页，否则使用已有 Facebook 页面；自定义活跃保留选中页面的地址，Reels 已在视频页面时也保留当前视频。取消好友请求沿用当前活动标签页。这些操作可能改变页面内容。账号识别使用临时后台页面；换头像使用独立任务页，打开编辑窗口、上传和保存时会前置窗口并激活任务页。运行浏览时，应保留目标 Facebook 页面为活动页面。

访问 `https://www.facebook.com/?fb_bridge_auto_extension` 可直接启动首页活跃。点击停止后，当前浏览器会话内禁止该参数自动重启，直到再次手动启动活跃；非 Facebook 网站上的同名参数不起作用。

停止时先取消尚未完成的启动和导航等待，再停止该浏览器全部 Facebook 标签页的活跃控制器，清理等待计时器及事件监听，收到停止确认后列表才显示“空闲”。旧版脚本存在无法追踪的计时器时，会刷新该旧任务页一次以清理；新版任务正常停止不刷新、不跳转。停止失败或 10 秒内没有收到确认，会在执行结果列显示错误，不会提前报告成功。

## 随机更换头像

1. 将图片放在同一个本机目录中，在“头像目录”输入路径或点击“选择目录”。
2. 选择一个或多个已连接、已识别账号，点击“换头像”。
3. 软件随机打乱目录中的非空 JPG、JPEG、PNG 或 WebP 文件，为本批次账号逐张分配，图片足够时不重复；发送绝对路径和已识别的个人主页地址。
4. 扩展新建后台任务页打开 `/me`，确认登录账号与列表记录一致。
5. 激活任务页，找到“编辑头像”；另一种布局则点击主页头像，在头像菜单内选择“Choose profile picture / 选择头像”，不会点击“See profile picture”。临时附加 Chrome `debugger`，优先定位头像编辑窗口内的文件控件；否则拦截上传按钮的文件选择器，通过 `DOM.setFileInputFiles` 填入图片路径。
6. 等待上传和裁剪窗口可保存，再检查任务页账号，点击“保存”。默认使用 Facebook 当前的裁剪设置，不自动调整构图。
7. 保存前再次激活任务页并向后台登记本次提交。保存窗口关闭后，检查成功提示或个人主页头像图片变化；若保存引起页面跳转、脚本上下文中断，后台尝试重新读取同账号头像复核。没有充分证据时标记“待确认”，不重试提交。回传结果，释放调试器，只关闭本次创建的任务页。

头像目录输入或选择后自动保存到 `conf/config.json`，下次启动恢复。源码运行时配置在 `server.py` 所在目录下；打包运行时在 `server.exe` 所在目录下，不使用工作目录或 PyInstaller 临时解压目录。目录必须可写，写入失败会提示。配置文件损坏或缺失时使用空目录重新选择；文件采用临时文件替换方式保存。开始更换头像前会先停止活跃，避免两个流程同时操作页面。

只读取所选目录直接包含的文件，不递归子目录。可用图片少于本批次账号数时，开始前提示一次，然后在图片全部用完后重新随机打乱复用；有多张图片时避免相邻账号使用同一张。去重按图片文件分配，不判断不同文件的图像内容是否相同，也不记录历次批次使用情况。不会删除或移动原文件。同一浏览器配置不会同时启动两次换头像。

| 结果 | 含义 |
| --- | --- |
| 头像已更新 | 已提交保存，并检测到页面成功提示或头像图片变化 |
| 待确认 | 已点击保存，但窗口关闭、页面跳转或其他中断导致无法充分确认，请自行检查个人主页；执行结果保留原因 |
| 执行失败 | 提交前账号变化、登录验证、文件控件缺失、上传/保存超时、任务页关闭，或页面明确报错；详情显示在“执行结果”列 |

用户切换其他标签页不会改变换头像目标，但关键步骤会重新激活任务页，可能打断正在使用的浏览器窗口。不要操作任务页里的头像编辑窗口；关闭、导航任务页或切换 Facebook 登录账号可能使任务失败或待确认。网络中断发生在提交保存之后时，头像可能已经更新，应核对后再重试。

当前匹配简体中文、繁体中文和英文按钮。Facebook 的页面布局、按钮文字、裁剪流程或上传限制发生变化时，可能需要调整 `change_avatar.js`。扩展没有绕过账号验证，也没有通过 Facebook 服务端接口核实最终持久化结果。

## 扩展权限

| 权限 | 用途 |
| --- | --- |
| `tabs`、`scripting` | 管理任务页、读取账号信息并执行页面脚本 |
| `debugger` | 将本机图片路径交给头像上传控件，并触发上传按钮点击 |
| Facebook 主机权限 | 在 Facebook 页面运行自动化脚本 |
| `fbcdn.net`、`fbsbx.com` 主机权限 | 读取 Facebook 头像图片并生成列表缩略图 |
| 本机主机权限 | 与本地控制软件通信 |
| `storage`、`alarms` | 保存当前会话的自动启动禁用状态、唤醒重连 |
| `unlimitedStorage` | 历史保留权限，当前流程不需要大量存储 |

换头像期间浏览器可能显示调试提示。不要在任务页打开开发者工具或取消调试，否则自动上传可能中断。

## 更新与打包

修改源码后，在扩展管理页面点击“重新加载”，并重启本地软件。已有的 `dist/server.exe` 不会自动包含新的 Python 源码。

```powershell
python -m PyInstaller --noconfirm --onefile --windowed --name server --specpath build --icon "WS Browser Bridge/icon/bridge.ico" --add-data "WS Browser Bridge/icon;WS Browser Bridge/icon" server.py
```

上述 Windows 命令包含软件窗口图标和扩展图标资源，输出为 `dist/server.exe`。本机已有的 `server.spec` 也已配置图标，可使用 `python -m PyInstaller --noconfirm server.spec`；仓库目前将该本机配置、`build`、`dist` 和 `release` 设为忽略文件。

```text

config_store.py                  软件目录定位、头像目录配置读写
server.spec                      本地打包配置
WS Browser Bridge/
  manifest.json                  扩展入口和权限
  bg.js                          连接、账号识别、标签页及上传调度
  popup.html / popup.js          扩展操作面板
  activity_runtime.js            统一活跃生命周期、取消与操作暂停
  activity_interactions.js       低频互动、单次上限、定位校验和去重
  tools.js                       首页、小组浏览
  auto_reels.js                  Reels 浏览
  cancel_friend_requests.js      取消已发送好友请求
  change_avatar.js               头像编辑、上传控件和保存状态识别
  icon/bridge-*                  插件及本地软件图标
tools/create_icons.py            图标生成工具，需要 Pillow
tests/                          通信和账号识别回归测试
```

`offscreen.html` 和 `offscreen.js` 是历史实现，当前 manifest 未启用。

```powershell
node --test tests/activity.test.cjs tests/activity_interactions.test.cjs tests/avatar_bridge.test.cjs tests/avatar_page.test.cjs
python -m unittest discover -s tests -p 'test_*.py'
python tools/check_ui.py
node tools/check_activity_browser.cjs
node tools/check_avatar_browser.cjs
```

单元测试模拟 Chrome API，验证停止取消、重复启动、导航竞争、重连退避、任务页隔离、账号变化、上传、保存结果及异常清理；Python 测试覆盖配置路径、本机 WebSocket 断开和账号定位，界面检查覆盖头像与窗口布局。两个浏览器检查脚本需要安装 Playwright 且本机有 Chrome：`check_activity_browser.cjs` 检查滚动及翻页；`check_avatar_browser.cjs` 检查直接编辑、头像菜单、文件上传和保存确认。测试地址全部拦截成本地内容，不访问真实账号。上述测试不登录真实 Facebook，也不能证明所有账号页面布局都适用。
